# TraeWork 每日自动签到工具

> 🚀 全自动完成 TraeWork / Trae CN 每日签到领取积分。  
> 具备**全自动环境检测**、**开机自启**、**屏幕右下角弹窗通知**、**已签到自动跳过**、**零手动配置**等特性。

---

## 📖 项目背景与调试复盘

在 Trae 的新积分体系下，每日签到送 **200 积分**（一个月累计可领 6,000+ 积分）。但日常使用中经常容易忘记手动打开客户端签到，一个月下来白白损失好几千积分。

论坛上此前有社区作者分享了初始的自动签到脚本（[传送门](https://forum.trae.cn/t/topic/178479)），但在实际下载与使用调试过程中，发现了以下几处硬伤：

1. **路径与版本强耦合**：
   - 原版 `checkin.js` 固定写死读取 `%APPDATA%\TRAE SOLO CN\...`，而很多用户本机实际运行的是 `Trae CN`（TraeCode）或非默认盘符；
   - 原版 `run_checkin.cmd` 写死了特定盘符下的可执行文件路径，一旦路径不存在直接中断报错。
2. **Windows CMD 编码冲突引发语法崩溃与“双击闪退”**：
   - 原版批处理文件为 UTF-8 编码且含有中文注释，在 Windows 默认的 GBK（CP936）代码页下直接导致命令解析器指针错位，连基础的 `set` 和 `if` 语句都被割裂报系统错误；
   - 加上脚本末尾没有暂停指令，导致用户双击时“一闪而过”瞬间退出（这也正是社区原帖楼下众多用户反馈“拖入 CMD 报错”的根本原因）。
3. **官方 API 安全校验升级（报错 `code: 9004`）**：
   - 官方签到接口进行了加固，缺少设备指纹校验会直接判定为参数缺失并返回 `code: 9004` 拒绝请求。
4. **高峰期官方服务器限流（报错 `code: 9074`）**：
   - 早晚高峰期官方接口频繁出现并发限流，原脚本缺乏重试机制，遇到 9074 直接中断退出。
5. **脚本碎片化，缺乏真正无感的开机自启与反馈机制**：
   - 原项目依赖多个独立的 `.ps1`、`.vbs` 脚本，不仅增加学习成本，而且缺乏开机静默运行并向用户弹窗通知结果的完整体验。

## 🌟 核心功能特性

1. **零配置开箱即用（全自动检测）**
   - 程序下载解压后即可直接使用，**无需手动填写任何 Token、Cookie 或修改安装路径**。
   - 自动全局动态扫描计算机中所有匹配 `*trae*` 的应用目录（包括 `Trae CN`、`TRAE SOLO CN`、`Trae` 等各种官方版本）。
   - 自动提取并解密登录凭据，自动校验 Token 有效期与最新活跃状态，智能选择最合适的客户端配置。

2. **开机自动启动，屏幕右下角弹出结果提醒**
   - 提供极简一键安装脚本，开机登录进入 Windows 桌面后系统自动在后台执行签到。
   - 签到执行完毕后，**屏幕右下角自动弹出 Windows 系统级原生通知**，清晰展示官方返回消息与获得积分详情（如：*“TraeWork 签到成功，恭喜获得 200 积分！”* 或 *“今日已完成签到，自动跳过”*）。

3. **智能防重复与自动跳过**
   - 执行前实时向官方接口查询当日签到状态：
     - **若今日已签到**：自动跳过领取步骤，右下角弹出提示后约 1 秒平稳退出，**不驻留后台、零内存占用**。
     - **若今日未签到**：自动发起领取，领取成功后在右下角展示积分并写入日志。

4. **官方接口风控防御与故障自愈**
   - **防御 `code: 9004`（参数错误）**：自动提取补齐客户端设备指纹（`X-Machine-Id`、`X-Device-Id`、`X-User-Id` 等请求头），彻底杜绝官方新版接口参数缺失报错。
   - **防御 `code: 9074`（服务器限流/繁忙）**：内置指数退避重试算法，高峰期自动随机等待 15~30 秒后重试（默认 5 次），显著提升签到成功率。

5. **历史运行日志可追溯**
   - 每次手动执行或开机后台自动签到的状态、时间戳与积分明细，均会自动持久化追加保存至 `checkin.log`。

## 📂 项目文件列表（极简架构，仅 4 个核心脚本）

项目经过去重与架构精简，移除了所有多余杂乱的辅助脚本，仅保留最直观的核心文件：

| 文件名 | 类型 | 功能说明 |
| :--- | :--- | :--- |
| **`install_autostart.cmd`** | 一键安装 | **唯一安装脚本**。双击即可一键开启开机自动签到（无需管理员权限，零学习成本）。 |
| **`uninstall_autostart.cmd`** | 一键卸载 | **唯一卸载脚本**。双击即可一键彻底清理开机自启任务。 |
| **`run_checkin.cmd`** | 执行入口 | 手动执行器。优先调用系统 Node，无 Node 时自动探测本机任何 `*trae*.exe`。双击保留窗口防闪退。 |
| **`checkin.js`** | 核心脚本 | 负责动态扫描客户端凭据、AES 本地解密、请求头装配、签到状态查询、智能跳过、右下角系统弹窗与日志写入。 |
| **`checkin.log`** | 运行日志 | 历史运行日志文件。记录每次签到的日期时间、执行结果、获得积分详情或自动跳过提示。 |
| **`readme.md`** | 项目文档 | 本说明文档。 |

## 📖 使用指南

### 方式一：一键开启开机自动签到（强烈推荐）

1. 直接双击运行 **`install_autostart.cmd`**。
2. 看到 `[OK] Auto check-in task installed successfully!` 提示后按任意键关闭。
3. **效果**：
   - 以后每次开机登录 Windows 桌面后，系统将自动在后台拉起签到。
   - 签到完成后，**屏幕右下角自动弹出气泡提示官方返回结果与积分**。
   - 若当天已签到，自动跳过并弹出提示。
   - 随时可打开 `checkin.log` 查看每日历史记录。

> 💡 **如需关闭开机自启**：随时双击运行 **`uninstall_autostart.cmd`** 即可完全移除。

---

1. 双击运行 **`run_checkin.cmd`**。

## 🔒 安全性与隐私说明

- **100% 纯本地运行**：凭据解密（AES-128-CBC + SHA-512）基于原生 WebCrypto API 在本地计算完成，不依赖外部未知组件。
- **绝不上传或泄露敏感凭据**：日志与控制台仅显示脱敏的用户 ID，绝不打印或外泄完整的 JWT Token。
- **只读模式保护**：程序对本地客户端的 `storage.json` 采取严格的**只读**操作，绝不修改客户端本地任何配置文件。
