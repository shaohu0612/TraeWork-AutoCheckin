# TraeWork 每日自动签到工具

> 🚀 全自动完成 TraeWork / Trae CN 每日签到领取积分。  
> 具备**全自动环境检测**、**开机自启**、**屏幕右下角弹窗通知**、**已签到自动跳过**、**零手动配置**等特性。

---

## 📖 项目背景与调试复盘

在 Trae 的新积分体系下，每日签到送 **200 积分**（一个月累计可领 6,000+ 积分）。但日常使用中经常容易忘记手动打开客户端签到，一个月下来白白损失好几千积分。

论坛上此前有社区作者分享了初始的自动签到脚本（[传送门](https://forum.trae.cn/t/topic/178479)），但在实际下载与使用调试过程中，发现了以下几处硬伤：

1. **路径与版本强耦合**：
   - 原版 `checkin.js` 固定写死读取 `%APPDATA%\TRAE SOLO CN\...`，而很多用户本机实际运行的是 `Trae CN`（TraeCode）或非默认盘符；
   - 原版 `run_checkin.cmd` 写死了特定盘符下的可执行文件路径，一旦路径不存在直接中断报错。
2. **Windows CMD 编码冲突引发语法崩溃与“双击闪退”**：
   - 原版批处理文件为 UTF-8 编码且含有中文注释，在 Windows 默认的 GBK（CP936）代码页下直接导致命令解析器指针错位，连基础的 `set` 和 `if` 语句都被割裂报系统错误；
   - 加上脚本末尾没有暂停指令，导致用户双击时“一闪而过”瞬间退出（这也正是社区原帖楼下众多用户反馈“拖入 CMD 报错”的根本原因）。
3. **官方 API 安全校验升级（报错 `code: 9004`）**：
   - 官方签到接口进行了加固，缺少设备指纹校验会直接判定为参数缺失并返回 `code: 9004` 拒绝请求。
4. **高峰期官方服务器限流（报错 `code: 9074`）**：
   - 早晚高峰期官方接口频繁出现并发限流，原脚本缺乏重试机制，遇到 9074 直接中断退出。
5. **脚本碎片化，缺乏真正无感的开机自启与反馈机制**：
   - 原项目依赖多个独立的 `.ps1`、`.vbs` 脚本，不仅增加学习成本，而且缺乏开机静默运行并向用户弹窗通知结果的完整体验。

## 🌟 核心功能特性

1. **零配置开箱即用（全自动检测）**
   - 程序下载解压后即可直接使用，**无需手动填写任何 Token、Cookie 或修改安装路径**。
   - 自动全局动态扫描计算机中所有匹配 `*trae*` 的应用目录（包括 `Trae CN`、`TRAE SOLO CN`、`Trae` 等各种官方版本）。
   - 自动提取并解密登录凭据，自动校验 Token 有效期与最新活跃状态，智能选择最合适的客户端配置。

2. **开机自动启动，屏幕右下角弹出结果提醒**
   - 提供极简一键安装脚本，开机登录进入 Windows 桌面后系统自动在后台执行签到。
   - 签到执行完毕后，**屏幕右下角自动弹出 Windows 系统级原生通知**，清晰展示官方返回消息与获得积分详情（如：*“TraeWork 签到成功，恭喜获得 200 积分！”* 或 *“今日已完成签到，自动跳过”*）。

3. **智能防重复与自动跳过**
   - 执行前实时向官方接口查询当日签到状态：
     - **若今日已签到**：自动跳过领取步骤，右下角弹出提示后约 1 秒平稳退出，**不驻留后台、零内存占用**。
     - **若今日未签到**：自动发起领取，领取成功后在右下角展示积分并写入日志。

4. **官方接口风控防御与故障自愈**
   - **防御 `code: 9004`（参数错误）**：自动提取补齐客户端设备指纹（`X-Machine-Id`、`X-Device-Id`、`X-User-Id` 等请求头），彻底杜绝官方新版接口参数缺失报错。
   - **防御 `code: 9074`（服务器限流/繁忙）**：内置指数退避重试算法，高峰期自动随机等待 15~30 秒后重试（默认 5 次），显著提升签到成功率。

5. **历史运行日志可追溯**
   - 每次手动执行或开机后台自动签到的状态、时间戳与积分明细，均会自动持久化追加保存至 `checkin.log`。

6. **全系统与多环境兼容性保障（零门槛普适）**
   - **零依赖运行**：未安装 Node.js 的电脑无需额外配置开发环境，启动器自动通过 Windows 注册表与路径自适应探测借用 Trae 客户端内置的现代 Node 引擎（v22+）。
   - **智能运行时降级保护**：若本机系统 PATH 中安装了旧版 Node.js（< 18），启动器会自动检测 API 支持度并自动平滑降级至 Trae 内置的高版本运行时，避免因缺少原生 `fetch` 导致崩溃。
   - **全盘符与任意自定义路径兼容**：支持标准 `%LOCALAPPDATA%`、`%ProgramFiles%`、注册表卸载项及各大盘符（C、D、E、F 等），无论将 Trae 安装在何处均能自动秒级识别。
   - **跨平台多系统原生支持**：核心 `checkin.js` 采用原生跨平台路径与 WebCrypto 规范，内置 Windows（Toast+托盘）、macOS（`osascript`）与 Linux（`notify-send`）桌面通知，Mac/Linux 用户在终端执行 `node checkin.js` 亦可无缝使用。
   - **路径特殊字符容错与防误伤保护**：安装脚本已针对包含空格、括号或中文路径进行安全参数化处理；卸载脚本精准清理本工具专有自启项，绝不误删用户原有的 Trae 桌面或开机快捷方式。

## 📂 项目文件架构

项目采用模块化跨平台设计，移除了多余冗余脚本，为各平台提供统一优雅的交互体验：

| 文件名 | 适用平台 | 功能说明 |
| :--- | :--- | :--- |
| **`manage_autostart.cmd`** | Windows | **Windows 双击入口**。双击即可快速拉起交互式管理菜单。 |
| **`manage_autostart.ps1`** | Windows | **Windows 交互控制台**。纯中文界面，支持键盘 `↑ / ↓` 箭头移动光标与回车确认。 |
| **`run_checkin.cmd`** | Windows | **Windows 执行器**。优先使用 Node，无 Node 时穿透注册表自动探测 Trae 运行时。 |
| **`manage_autostart.sh`** | macOS / Linux | **Unix 自启管理脚本**。纯中文界面，支持键盘 `↑ / ↓` 方向键选择，配置 LaunchAgent / XDG 自启。 |
| **`run_checkin.sh`** | macOS / Linux | **Unix 执行器**。自动探测系统 Node 或 Trae 客户端内置 Electron 运行时。 |
| **`checkin.js`** | 全平台通用 | **核心逻辑引擎**。凭据动态扫描、本地 AES 解密、风控头装配、状态查询、桌面通知与日志写入。 |
| **`log/checkin.log`** | 本地运行日志 | 每次执行的详细记录（位于 `log/` 目录，自动由 `.gitignore` 保护，绝不上载泄露）。 |
| **`doc/`** | 架构与技术文档 | 包含底层通信链路逆向、主进程行为分析与签到实现白皮书。 |
| **`readme.md`** | 项目文档 | 本说明文档。 |

## 📖 使用指南

### 🪟 Windows 系统使用

#### 1. 管理开机自动签到（安装 / 卸载）
- 直接双击运行 **`manage_autostart.cmd`**（或右键运行 `manage_autostart.ps1`）；
- 弹出纯中文交互式控制台界面，**支持键盘 `[↑ / ↓]` 方向键移动光标高亮，按 `[Enter]` 确认选择**（亦可直接按下键盘数字快捷键）：
  - **`[1] 安装开机自启任务`**：开机登录 Windows 桌面后后台静默签到并在右下角弹窗通知；
  - **`[2] 卸载开机自启任务`**：彻底移除已配置的自启项；
  - **`[3] 立即测试执行签到`**：即时发起签到并查看详细过程与官方返回积分；
  - **`[0] 退出管理程序`**：退出交互界面。

#### 2. 手动单次运行
- 直接双击运行 **`run_checkin.cmd`** 即可，执行完毕自动保留窗口查看输出。

---

### 🍏 macOS / 🐧 Linux 系统使用

#### 1. 管理登录自动签到（安装 / 卸载）
打开终端进入本程序目录，运行自启管理脚本：
```bash
./manage_autostart.sh
```
- 同样支持 **键盘 `[↑ / ↓]` 方向键移动光标** 与 **数字键快捷选择**：
  - **选项 `1`**：
    - **macOS**：自动在 `~/Library/LaunchAgents` 创建开机登录自启服务；
    - **Linux**：自动在 `~/.config/autostart` 创建桌面会话登录自启项。
  - **选项 `2`**：彻底卸载清理自启服务；
  - **选项 `3`**：立即运行一次测试。

#### 2. 手动单次运行
在终端中直接运行：
```bash
./run_checkin.sh
# 或者
node checkin.js
```

## 🔒 安全性与隐私说明

- **100% 纯本地运行**：凭据解密（AES-128-CBC + SHA-512）基于原生 WebCrypto API 在本地计算完成，不依赖外部未知组件。
- **绝不上传或泄露敏感凭据**：日志与控制台仅显示脱敏的用户 ID，绝不打印或外泄完整的 JWT Token。
- **只读模式保护**：程序对本地客户端的 `storage.json` 采取严格的**只读**操作，绝不修改客户端本地任何配置文件。
